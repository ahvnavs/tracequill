# CLAIM SPECIFICATION (v1.1)

This document defines the normative contract between the Rust capture agent (`bokuei-agent`) and the Go core (`bokuei`).

> **Note on v1.1**: Version 1.1 only adds predicates and ref kinds. The canonical JSON serialization algorithm, field schema, and normative test vectors 1–5 are frozen and remain strictly byte-identical and hash-identical with v1.0.

## 1. Claim Structure

A claim is an assertion about an entity, captured at a specific point in time by an identified source within a specific scope.

A claim JSON object contains the following eight fields in top-level object notation:

| Field | Type | Description |
|---|---|---|
| `subject` | String | A typed reference URI: `ref://<kind>/<id>`. |
| `predicate` | String | Dot-separated predicate identifier (e.g., `run.command`). |
| `object` | Object | The target object descriptor (see Section 2). |
| `observed_at` | String | RFC3339 UTC timestamp with `Z` suffix (e.g., `2026-10-07T12:00:00Z`). |
| `source` | Object | Origin information: `{"group": "...", "id": "...", "method": "..."}`. |
| `scope` | String | Scope reference URI: `ref://host/<id>` or `ref://zone/<id>`. |
| `evidence_hash` | String | Hex-encoded SHA-256 of raw supporting evidence payload (64 chars). |
| `redaction` | String | Redaction status: `"none"`, `"redacted"`, or `"partial"`. |

### Allowed Entity Kinds in Refs (`ref://<kind>/<id>`)
- `host`
- `run`
- `process`
- `artifact`
- `package`
- `gpu`
- `endpoint`
- `zone`
- `service`
- `dataset`
- `interface`
- `route`
- `capability`

Allowed characters in `<id>` are `[a-zA-Z0-9_.\-:]` (including colons for endpoints such as `host:port`).

### Object Value Descriptors
The `object` field is a JSON object with:
- `kind`: Exactly one of `"ref"`, `"text"`, `"int"`, `"bool"`, `"json"`. (Floating-point numbers are prohibited; decimals must be formatted as strings).
- `value`: The value matching the kind:
  - `ref`: String (a valid `ref://` URI)
  - `text`: String
  - `int`: Integer (64-bit signed integer)
  - `bool`: Boolean (`true` or `false`)
  - `json`: Canonical JSON string or JSON value

## 2. Canonical Serialization Algorithm

Canonical bytes must be generated by applying the following deterministic rules:
1. Encoding must be UTF-8 without byte-order marks.
2. Object keys must be sorted lexicographically by UTF-8 Unicode codepoint order at all nesting depths.
   Top-level order:
   `evidence_hash`, `object`, `observed_at`, `predicate`, `redaction`, `scope`, `source`, `subject`.
   `object` order: `kind`, `value`.
   `source` order: `group`, `id`, `method`.
3. No whitespace is permitted between tokens (no spaces after colons, commas, or outside brackets/braces).
4. Numbers must be formatted without exponent notation unless required, and floats are disallowed.
5. All 8 fields must be present.
6. The `claim_id` is defined as:
   ```
   claim_id = sha256(canonical_claim_bytes)
   ```
   represented as a 64-character lowercase hexadecimal string.

## 3. Normative Test Vectors

The following 5 test vectors must produce identical canonical bytes and SHA-256 digests in both the Go core and the Rust agent:

### Vector 1: Standard run command claim
**Raw Input:**
```json
{
  "subject": "ref://run/run-001",
  "predicate": "run.command",
  "object": {"kind": "text", "value": "python train.py --epochs 10"},
  "observed_at": "2026-10-07T10:00:00Z",
  "source": {"group": "agent", "id": "agent-host-alpha", "method": "procfs"},
  "scope": "ref://host/alpha",
  "evidence_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "redaction": "none"
}
```
**Canonical Bytes:**
```json
{"evidence_hash":"e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855","object":{"kind":"text","value":"python train.py --epochs 10"},"observed_at":"2026-10-07T10:00:00Z","predicate":"run.command","redaction":"none","scope":"ref://host/alpha","source":{"group":"agent","id":"agent-host-alpha","method":"procfs"},"subject":"ref://run/run-001"}
```
